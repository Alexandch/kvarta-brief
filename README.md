# Кварта — кофейная мастерская

Авторский лендинг небольшой минской обжарки. Это не интернет-магазин: посетитель знакомится с зерном, условиями доставки и отправляет заявку; менеджер уточняет детали по телефону.

## Что сделано

- Дизайн для «Кварты»: тёплая бумажная палитра, зелёный и терракотовый акценты, выразительная типографика, подписи и композиция с журнальным ритмом.
- Адаптивная главная страница: история мастерской, три лота кофе с ценами, подписка, самовывоз и доставка.
- Форма с выбором интереса и комментарием. Белорусский мобильный номер проверяется в браузере и на сервере; ошибку отправки видно посетителю.
- `POST /api/lead` сохраняет имя, номер, интерес, комментарий и рекламные метки. Повторная заявка с того же номера в течение 10 минут блокируется в базе; блокировка сериализует параллельные отправки этого номера.
- UTM-метки, `gclid`, `fbclid`, `yclid`, реферер, первая страница визита и страница отправки сохраняются вместе с заявкой.
- Локальная и production-среда используют PostgreSQL: Docker Compose поднимает локальную базу, Netlify подключается к внешнему PostgreSQL в Supabase.

## Быстрый запуск через Docker Compose

Нужен установленный и запущенный Docker Desktop с поддержкой Compose.

```bash
docker compose up -d --build
```

Откройте `http://localhost:3000`. Compose собирает образ Next.js, ждёт готовности PostgreSQL и запускает сайт и базу. Контейнеры используют `restart: unless-stopped`, поэтому после перезагрузки компьютера приложение поднимется снова, когда запустится Docker Desktop. Чтобы не запускать сам Docker Desktop вручную, включите **Settings → General → Start Docker Desktop when you sign in**. Чтобы остановить приложение, выполните `docker compose down`; данные базы останутся в Docker volume.

Если меняли код, обновите образ командой `docker compose up -d --build`. Локальные заявки можно просмотреть в таблице `leads` контейнера PostgreSQL. Для полного сброса локальной базы вместе с заявками используйте `docker compose down -v`.

## Запуск Next.js вне контейнера

Нужны Node.js 22 и npm.

```bash
Copy-Item .env.example .env.local
npm install
npm run db:up
npm run dev
```

Откройте `http://localhost:3000`. `.env.local` подключает приложение к PostgreSQL, поднятому в Compose. `npm run db:down` останавливает только базу. Production-сборка: `npm run build`, затем `npm start`.

## База данных и выбор хранения

Заявки хранятся в PostgreSQL. Для этой формы важны связь полей одной заявки, фильтрация по дате и рекламному источнику, поиск повторов по телефону и понятный просмотр заявок менеджером. SQL-таблица даёт эти возможности без ручного чтения JSON-файла; рекламные метки при этом остаются гибким полем `jsonb`.

`create_kvarta_lead` выполняет проверку телефона и запись в одной транзакции. Короткая блокировка по хешу номера не позволяет двум одновременным запросам создать дубликат, а заявки с разными номерами не блокируют друг друга. JSON-файл на диске не выбран, потому что диск функции Netlify не подходит как постоянное хранилище между запусками и деплоями.

Локально используется обычный официальный образ PostgreSQL в Docker Compose. В продакшене используется управляемый PostgreSQL в Supabase: данные переживают перевыкладку приложения и доступны в Table Editor. Код приложения в обеих средах подключается через `pg` и выполняет одну и ту же SQL-функцию.

### Подключение Supabase к Netlify

Создайте Supabase project и один раз примените содержимое [`db/init/001_create_leads.sql`](db/init/001_create_leads.sql) через SQL Editor Supabase. Затем в панели проекта откройте **Connect** и скопируйте строку **Shared Pooler → Transaction mode**. Подставьте пароль базы данных, URL-кодируя специальные символы.

В Netlify добавьте переменную окружения `DATABASE_URL` со строкой Supabase и запустите новый deploy. Для шифрования соединения добавьте к URI параметр `sslmode=require` (если его нет). Для serverless-среды используйте [transaction pooler Supabase](https://supabase.com/docs/guides/database/connecting-to-postgres), рассчитанный на короткие соединения функций; прямое подключение к Postgres оставлено для самой базы и миграций. После отправки формы записи видны в Supabase Table Editor → `public.leads`. Храните URL с паролем только в переменных окружения Netlify и `.env.local`, не добавляйте их в Git.

## Структура проекта

- `components/landing.tsx` — тексты, каталог, поля формы и сценарии интерфейса.
- `app/globals.css` — адаптивный дизайн.
- `app/api/lead/route.ts` — серверная валидация и запрос к PostgreSQL.
- `db/init/001_create_leads.sql` — таблица, индекс и атомарная функция создания заявки.
- `Dockerfile`, `docker-compose.yml` — контейнеризация Next.js и локального PostgreSQL.
- `netlify.toml` — команда сборки и версия Node для Netlify.

## Процесс и допущения

- Визуальная концепция, структура страницы, тексты, верстка, форма, API, SQL-схема, Docker-конфигурация и документация подготовлены с помощью Codex по исходному брифу. В брифе сказано, что факты о клиенте вымышленные; цены, адрес и часы работы взяты оттуда.
- Бриф просит менеджера перезвонить в течение 10 минут, но не задаёт расписание обработки вне рабочих часов. Срок показан на сайте и не привязан к часам в серверной логике.
- Telegram-дублирование обозначено в брифе как необязательное и не добавлено: для него нужны токен бота и чат.
- Платёжная корзина не нужна по ТЗ.
- Этот репозиторий не содержит экспорта сессии Claude Code. Если проверяющий требует именно `/export` или скриншоты сессии, приложите реальный экспорт своего процесса разработки; история Codex не подменяется вымышленным логом.
- Принимаются только белорусские мобильные номера `+375 25`, `29`, `33` и `44`.
